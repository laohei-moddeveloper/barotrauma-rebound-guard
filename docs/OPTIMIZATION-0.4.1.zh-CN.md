# 0.4.1 优化、适配与验证报告

目标：Barotrauma 1.13.5.0，LuaCs 官方提交 `c6e8829143c98162ed376aee33eb9799602365ac` 的 Windows 客户端和专用服务端。

## 基线与实际新增

发布前已同步远端主线 `03ae30e`，保留 10 月 21 日发布的单次 LuaCs 包装、实时状态标签索引、附近索引冻结快照、增量候选缓存、队列计数索引和弱引用队列缓存。它们不是本轮首次发明的功能，不能把相对原版的全部收益当作本轮增量。

本轮新增：

| 位置 | 具体改动 | 作用与限制 |
| --- | --- | --- |
| `AuditedBuild.cs` 及各功能兼容检查 | 对新游戏/Core/Farseer 原生运行时做完整 SHA256 白名单 | 恢复因旧版保护而关闭的路径；公共编译引用不当作运行时白名单 |
| `LuaArgumentConversion.cs`、`LuaDirectBridge.cs` | 同类型参数快路径、弱引用类型对缓存、保留真实隐式转换调用 | 避免重复构造表达式树；修复已发布直接包装遗漏隐式转换与 null 错误边界的问题 |
| `LuaBridgeOptimizer.cs` | 原 `ClearAll` 未运行或有竞争补丁时不提前丢弃活跃状态 | 保留后续原生包装恢复与热重载行为 |
| `FeatureInstaller.cs`、`Plugin.cs` | 按功能捕获安装异常并回滚新增加的自有补丁 | 一个 API/IL 失配不再直接撤销整包已成功功能；仍保留总初始化失败保护 |
| `NearbyItemIndex.cs` | 一次范围判断复用同一次实时位置读取 | 保留原距离条件及竞争补丁保护；不改变动态标签审计 |
| 安装与验证工具 | 当前 LuaCs 设置识别、独立 041 目录、新版本固定依赖下载、隔离跨平台验证入口 | 不替换游戏二进制，不修改用户的 C# 启用策略 |

## 二进制核对

对之前受支持的 1.13.4.0 官方构建与新 Windows 构建做解析后的 IL、局部变量、栈上限及异常区间比较：客户端 40,739 个方法体一致、26 个改变；服务端 27,498 个一致、23 个改变；Core 622 个一致、Farseer 1,973 个一致。相关补丁方法没有出现在改变列表中。网络更新修复、存档路径校验和 XML 修复没有被回滚。

这项静态比较不能单独证明依赖、字段布局或运行行为完全等价，因此另做真实程序集隔离回归。Linux 游戏构建有更多不同方法，未把其游戏程序集强行加入当前 Windows 白名单。

## 运行验证

最终结果存放在 `docs/validation/0.4.1/`。主机为 Linux/.NET 8，目标是原生 Windows 游戏程序集；没有启动游戏入口、潜艇战斗、渲染或实时多人会话。完整物理回归显式报告四逻辑处理器以覆盖并行分支，实际容器 CPU 资源仍有限。

新增回调差异检查包括：返回值优先级、ref/out、回调异常、参数类型错误、注册/删除中途变化、递归调用、保留参数表、回调中 Reset、真实 MoonSharp 回调、每次隐式转换、转换异常、后到的外部转换/工厂/清理补丁。原有延迟枚举挂钩检查继续保留。

用户后续指令要求立即收尾，一小时耐久计划因此取消。先前原型的中断计数单独标注，不作为最终整合版本的通过证据；最终版本执行短时压力、重复 Reset 和原生恢复检查。

## 性能解释

以下结果由最终验证 JSON 汇总。所有倍数都只对应指定的局部负载：

| 测试（每批 20,000 次调用） | 客户端 | 服务端 |
| --- | --- | --- |
| 无返回值/ref 参数耗时 | 17.835 → 8.504 ms（2.10 倍） | 17.678 → 8.845 ms（2.00 倍） |
| 上述线程分配 | 25.12 → 11.20 MB | 25.12 → 11.20 MB |
| Bool 返回线程分配 | 16.48 → 6.24 MB | 16.48 → 6.24 MB |
| Bool 返回局部耗时（有宿主调试指令影响） | 90.405 → 5.381 ms | 90.023 → 5.145 ms |

队列基准的“旧重建算法”是最初 0.4.0 的反例，不是 10 月 21 日已发布主线。计数队列及跨包缓存来自已发布主线，本轮是在新构建上恢复其适配。引用枚举两秒等待修复也来自已有代码，本轮重新验证。

完整物理步未建立稳定、显著的加速；不据此承诺物理/FPS 十倍。原生 Bool 返回测试含 `break` 调试指令，宿主对它的处理成本差异大，不能外推到 Windows 整场。无返回值且修改参数的测试更适合评估日常包装成本。

整局 FPS、加载总耗时、可见回弹和联机延迟没有可比实战数据。本轮消除了确定的失配与局部重复工作，不能把这写成三个问题已根治。
